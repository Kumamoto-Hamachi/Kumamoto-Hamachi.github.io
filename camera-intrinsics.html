カメラ内部パラメータ

前のページの締めくくりに u = fx·Xc/Zc + cx という式が顔を出しました。 ここでは、この式に出てくる数の素性を一つずつ確かめ、それらが 3×3 の行列 K に組み上がるまでを、 途中の計算を省かずに追いかけます。 ゴールは、OpenCV のキャリブレーションが返す cameraMatrix と distCoeffs の中身を、見て意味が分かる状態になることです。

K= fx0cx 0fycy 001
9 個のマスのうち、実際に意味を持つ数は fx, fy, cx, cy の 4 つだけ。 このページを読み終えると、この 4 つの役割がすべて説明できるようになります。

三つの座標系と二種類のパラメータ

「3D の点が写真のどのピクセルに写るか」という計算は、同じ点の住所を三つの座標系で順に書き換えていく旅です。 まず、その三つを紹介します。

世界座標系とは、カメラとは無関係に自分で決めた基準で 3D の位置を測る座標系です。 基準はどこでもかまいません。部屋の隅を原点にしてもよいし、机に貼ったマーカーの中心を原点にしてもよい （ArUco の姿勢推定では、マーカー中心を原点に取るのが習慣です）。 「世界」という大げさな名前がついていますが、意味するところは 「カメラの外に固定した、全員が共有するものさし」というだけのことです。

カメラ座標系は、カメラのレンズ中心（ピンホール）を原点として、カメラから見た向きで測る 3D 座標系です。 OpenCV では、カメラから見て右に Xc、下に Yc、レンズが向く前方に Zc を取ります。 Yc が下向きなのは、画像のピクセル座標が下向きに増えるのと軸の向きを揃えるためです。 前のページで「マーカーまでの距離」と呼んでいた Z は、この Zc のことでした。

ピクセル座標は、画像の左上隅を (0, 0) として、右に u、下に v と画素を数えた 2D の座標です。 画素の番号は 0 始まりなので、640×480 の画像では u は 0〜639、v は 0〜479 の値を取ります。 また、検出結果の (u, v) は画素と画素の間を指すことがあるので、整数とは限りません。

最初の矢印、世界座標からカメラ座標への書き換えを受け持つのが、回転行列 R と並進ベクトル t です。 書き換えは「R を掛けて軸の向きを揃え、t を足して原点をずらす」という形で行われます。 式で書くと (Xc, Yc, Zc) = R·(X, Y, Z) + t で、 この R と t を合わせて外部パラメータと呼びます。 カメラを三脚ごと動かせば R と t は変わります。

注意したいのは、t は「カメラの位置」そのものではないことです。 上の式に世界座標の原点 (X, Y, Z) = (0, 0, 0) を入れると、R·(0, 0, 0) は 0 なので答えは t そのもの。 つまり t は「世界座標の原点を、カメラから見た位置」です。 逆に、カメラ自身が世界座標のどこにいるかは −RTt という式で逆算します （RT は R の行と列を入れ替えた「転置行列」です）。 solvePnP の結果を読むときに取り違えやすい点なので、先にここで区別しておきます。

文章だけでは位置関係を想像しにくいので、三つの座標系が空間のどこにあるのかを 1 枚の絵にまとめます。 左の 3D 図は、カメラにも世界にも属さない第三者の視点から眺めた配置図です。 スライダーで眺める角度を変えながら、右のカメラ画像と見比べてください。

配置は本文の計算例と同じで、カメラの 0.5 m 先に一辺 0.1 m のマーカーが正対しています。 右下の隅 (0.05, 0.05, 0.5) とピンホールを結ぶ視線を延長すると（破線）、 Zc = 1 に置いた仮想スクリーンを (0.1, 0.1) で貫きます。 これが後半の STEP 1 で計算する正規化画像座標です。 マーカーがスクリーンより手前にあるぶん、スクリーン上の像は実物より大きくなることにも注目してください。 x′ = 0.05 ÷ 0.5 = 0.1 という割り算は、この相似拡大のことです。 方位角を 90° まで回すと、前のページの側面図とほぼ同じ構図になります。

視点をどれだけ回しても、右のカメラ画像は 1 px も動きません。 ピクセル座標を決めるのはカメラとマーカーの位置関係だけで、 図を眺める私たちの角度は計算のどこにも登場しないからです。

種明かしをすると、この 3D 図は 3D ライブラリを使わず、このページの式だけで描いています。 シーンの各点を「視点カメラ」の座標系に回転してから u = f·X/Z + cx で投影する—— スライダーが取り替えているのは、まさに回転行列 R です。

一方、二番目の矢印を受け持つ fx, fy, cx, cy と歪み係数は、 レンズとセンサの作りだけで決まる数なので、カメラをどこへ動かしても変わりません。 カメラの置き場所という「外側」の事情で決まるのが外部パラメータ、 カメラの構造という「内側」の事情で決まるのが内部パラメータ。名前の由来はこの対比にあります。 ただし「変わらない」のは置き場所についての話です。 ズームやフォーカスを回せばレンズの状態が変わり、出力解像度を切り替えれば 1 画素の実質的な大きさが変わるので、 そのたびに内部パラメータは別の値になります（キャリブレーションもやり直しです）。

このページの主役は二番目の矢印です。 以降の計算はすべてカメラ座標 (Xc, Yc, Zc) から出発します。 R と t の求め方（solvePnP）は、キャリブレーションを理解した後の話題です。

行列とベクトルの掛け算

K の話に入る前に、道具を一つだけ準備します。 必要な線形代数は「行列とベクトルの掛け算」ただ一つで、規則さえ知れば手計算できます。

ベクトルとは、いくつかの数を縦に一列に並べてひとまとめにしたものです。 3D の点の位置は「3 つの数を縦に並べたベクトル」として書けます。 行列とは、数を長方形の表の形に並べたものです。 このページで使うのは 3 行 3 列の行列だけです。

行列とベクトルの掛け算には決まった手順があります。 行列の行を左から右へ読みながら、ベクトルの上から下の成分と順番にペアで掛けて、全部足す。 これを行ごとに繰り返すと、行の数だけ答えが出て、新しいベクトルができます。

練習 1 — 2×2 で手順を確認する

1 行目の (2, 3) とベクトルの (10, 20) をペアで掛けて足すと 1 つ目の答え、 2 行目の (1, 0) と同じ (10, 20) で 2 つ目の答えが出ます。

2310 1020 = 2×10 + 3×201×10 + 0×20 = 20 + 6010 + 0 = 8010
練習 2 — K と同じ形の 3×3

次は、後で出てくる K とまったく同じ位置に 0 と 1 を置いた行列です。手順は変わりません。

203 021 001 10201 = 2×10 + 0×20 + 3×1 0×10 + 2×20 + 1×1 0×10 + 0×20 + 1×1 = 20 + 0 + 30 + 40 + 10 + 0 + 1 = 23411

0 のマスは相手の成分を消し、1 のマスは相手をそのまま通します。 1 行目を言葉にすると「1 つ目の成分を 2 倍して、3 を足す」。 つまりこの行列は、拡大（掛け算）と平行移動（足し算）を一度に実行する機械です。 K の中に 0 と 1 が多いのは手抜きではなく、必要な操作がこれだけだからです。

ピクセル座標までの三つのステップ

カメラ座標の点 (Xc, Yc, Zc) をピクセル座標 (u, v) に変える計算は、 「割る」「掛ける」「足す」の三つのステップに分解できます。 一つずつ、数値を入れて確かめます。 例として使うのは、カメラの 0.5 m 先に正対して置いた一辺 0.1 m のマーカーの右下の隅、 カメラ座標で (Xc, Yc, Zc) = (0.05, 0.05, 0.5) です （Yc は下向きが正なので、下の隅は符号がプラスになります）。

STEP 1 — 奥行きで割る

正規化画像座標

前のページの相似三角形は「画像上の位置は、横のずれと奥行きの比で決まる」と言っていました。 そこでまず、Xc と Yc をそれぞれ奥行き Zc で割ってしまいます。

x′ = Xc / Zc = 0.05 / 0.5 = 0.1
y′ = Yc / Zc = 0.05 / 0.5 = 0.1

この (x′, y′) を正規化画像座標と呼びます。 ピンホールからちょうど距離 1 の位置に仮想のスクリーンを置いたとき、点が写る場所に当たります。 メートルをメートルで割ったので単位は消えており、カメラの解像度にも機種にも依存しない純粋な比です。 レンズ歪みの計算（後述）は、この座標の上で行われます。

STEP 2 — fx を掛ける

比をピクセル数に直す

正規化画像座標はただの比なので、画素の数に換算する拡大率が要ります。 それが焦点距離（ピクセル単位）の fx と fy です。 fx = 800 px とは「正規化座標の 1 が 800 ピクセルに相当する」という換算率のことです。

fx · x′ = 800 × 0.1 = 80 （光軸から右に 80 px）
fy · y′ = 800 × 0.1 = 80 （光軸から下に 80 px）

この数はレンズとセンサの物理から来ています。 レンズの焦点距離（ここでは物理的な長さの方）を f = 3.6 mm、センサの画素 1 個の幅を 4.5 µm = 0.0045 mm とすると、

fx = f ÷ 画素 1 個の幅 = 3.6 ÷ 0.0045 = 800 px

fx と fy が別々に用意されているのは、画素が縦横で完全に同じ寸法とは限らないからです。 現代のセンサの画素はほぼ正方形なので、キャリブレーションの結果でも両者は近い値になります （実測で 800.3 と 801.1 のように微差が出るのが普通です）。

STEP 3 — cx, cy を足す

原点を画像の左上へ引っ越す

fx·x′ = 80 は「光軸の位置から右に 80 px」という、光軸を 0 とした位置です。 ところがピクセル座標の原点は画像の左上隅でした。 そこで、光軸が画像を貫く位置を足して、原点を左上基準に引っ越します。 この「光軸が画像面を貫く点」を主点と呼び、その座標が (cx, cy) です。

u = fx · x′ + cx = 80 + 320 = 400
v = fy · y′ + cy = 80 + 240 = 320

640×480 の画像なら主点はほぼ中央の (320, 240) ですが、 レンズの取り付けにはわずかな個体差があるため、実測すると中央から数ピクセルずれているのが普通です。 このずれも含めて測ることが、キャリブレーションの仕事の一つです。

まとめ — 三つのステップを一本の式に

三つを続けて書くと、前のページの締めに出てきた式そのものになります。

u = fx · Xc / Zc + cx
　 = 800 × 0.05 / 0.5 + 320
　 = 40 / 0.5 + 320
　 = 80 + 320
　 = 400
v = fy · Yc / Zc + cy
　 = 800 × 0.05 / 0.5 + 240
　 = 40 / 0.5 + 240
　 = 80 + 240
　 = 320

マーカーの右下の隅は、ピクセル座標 (400, 320) に写ります。 画像中心 (320, 240) から右下に 80 px ずつずれた位置です。

三つのステップを行列 K にまとめる

三つのステップのうち「掛ける」と「足す」は、練習 2 で見たとおり、行列の掛け算が一度に実行できる形です。 残る問題は「割る」で、割り算は行列の掛け算では表現できません。 そこで、割り算を最後まで先送りするという約束を作ります。

手順はこうです。 まだ Zc で割っていない 3 つの数を行列で一度に作っておき、 最後に「3 番目の成分で全体を割って、3 番目を 1 に直す」。 すると 1 番目と 2 番目が、求めたかった u と v になっています。 このように「3 つの数の組は、全体を何倍かしても同じ点を表す」と約束したうえで、 3 番目で割って (u, v, 1) の形に整えてから読む書き方を同次座標と呼びます。 名前は仰々しいですが、実体は「割り算を後回しにするための書き方」です。

記号のまま展開する

K とカメラ座標のベクトルを、練習 2 と同じ手順で掛けます。行ごとにペアで掛けて足すだけです。

fx0cx 0fycy 001 XcYcZc = fx·Xc + 0·Yc + cx·Zc 0·Xc + fy·Yc + cy·Zc 0·Xc + 0·Yc + 1·Zc = fxXc + cxZc fyYc + cyZc Zc

3 行目に (0, 0, 1) を置いた理由がここで分かります。 3 番目の成分として奥行き Zc をそのまま保存しておくためです。 最後に 3 番目で割ると、1 行目は fxXc/Zc + cx、 つまり STEP 1〜3 の式と一致します。

数値で展開する — 同じ点 (0.05, 0.05, 0.5)
8000320 0800240 001 0.050.050.5 = 800×0.05 + 0×0.05 + 320×0.5 0×0.05 + 800×0.05 + 240×0.5 0×0.05 + 0×0.05 + 1×0.5 = 40 + 0 + 1600 + 40 + 1200 + 0 + 0.5 = 2001600.5

3 番目の成分 0.5（= 保存されていた Zc）で全体を割ります。

u = 200 ÷ 0.5 = 400
v = 160 ÷ 0.5 = 320
　 0.5 ÷ 0.5 = 1 （3 番目が 1 に戻り、同次座標の約束が満たされた）

ステップ計算の答え (400, 320) と一致しました。 ステップ版は先に Zc で割り、行列版は後で割る。 本当に同じ計算なのか、行列版の 1 行目を Zc で割って確かめます。

(fx·Xc + cx·Zc) ÷ Zc = fx·Xc/Zc + cx·Zc/Zc = fx·Xc/Zc + cx

ステップ版の u の式に戻りました。 使ったのは「足し算の各項を別々に割ってよい」ことと「Zc/Zc = 1 と約分できる」ことの 2 つだけなので、 どんな数値でも両者は必ず一致します。

わざわざ行列にまとめる利点は、式が短くなることだけではありません。 世界座標からカメラ座標への変換（R と t）も行列で書けるため、 「世界座標 → ピクセル」の全行程を行列の掛け算の連鎖として一気に書き下せるようになります。 そして OpenCV の関数が cameraMatrix という 3×3 の配列を要求するのは、この K をそのまま渡しているからです。

レンズ歪みと歪み係数

ここまでの式は、光がまっすぐ進んで小さな穴を 1 点だけ通る、理想のピンホールを仮定していました。 実際のカメラは、穴の代わりにレンズで光を集めます。 レンズは明るさと引き換えに癖を持ち込みます。 ガラスの曲面は中心部と周辺部で光の曲げ方がわずかに違うため、まっすぐな物がわずかに曲がって写るのです。 安価な広角カメラで撮った写真の端で、直線の壁が弓なりに見える現象がそれです。

このレンズの癖を数式にしたものが歪み係数です。 理想のピンホールなら (x′, y′) に写るはずの点が、実際には少しずれた位置 (x″, y″) に写る。 そのずれ方を、いくつかの係数を持つ多項式で近似します。 歪みはレンズの中で起こるので、ピクセルに変換する前、正規化画像座標の段階で適用します。 K を掛けるのはその後です。

ずれの大部分は、点が光軸中心からどれだけ離れているかだけで決まります。 レンズは円形で、中心からの距離が同じなら癖も同じだからです。 この成分を放射歪みと呼び、係数 k1, k2, k3 で表します。 中心からの距離 r を使って、次の形で書きます。

放射歪みの式
r² = x′² + y′² （正規化座標で測った、中心からの距離の 2 乗）
倍率 m = 1 + k1·r² + k2·r⁴ + k3·r⁶
x″ = x′ · m
y″ = y′ · m

「点を中心から見て m 倍の位置に置き直す」という操作です。 m は r に依存するので、中心付近（r ≈ 0）ではほぼ 1 倍のまま、端に行くほど 1 からずれる。 これが「画像の端ほど歪む」の正体です。 役割の分担としては k1 が主役、k2 は r⁴ の係数なので端でだけ効く補正役、 k3 はさらに端に限って効く高次の補正で、意味のある値が求まるかどうかはレンズと撮影データしだいです。 なお本格的な魚眼レンズは歪みが大きすぎてこの多項式では表しきれないため、 OpenCV には cv2.fisheye という別のモデルが用意されています。

符号の読み方は次のとおりです。 k1 が負なら m < 1、つまり端の点ほど中心に引き寄せられ、 直線が外側にふくらむ樽型歪みになります（広角レンズに典型的）。 k1 が正なら端が外に引き出され、直線が内側にへこむ糸巻き型歪みになります（望遠レンズに出やすい）。

数値で展開する — k₁ = −0.2、画像の右下の縁に写るはずの点

理想のピンホールならちょうど画像の右下の縁 (u, v) = (640, 480) に写る点、 (x′, y′) = (0.4, 0.3) で計算します（k2 = k3 = 0 とします）。 画素の番号は 0〜639 でしたから、(640, 480) は特定の画素ではなく画像の縁を指す位置です。

r² = 0.4² + 0.3² = 0.16 + 0.09 = 0.25
m = 1 + k1·r² = 1 + (−0.2) × 0.25 = 1 − 0.05 = 0.95
x″ = x′ · m = 0.4 × 0.95 = 0.38
y″ = y′ · m = 0.3 × 0.95 = 0.285

あとはいつもどおり K でピクセルに直します（fx = fy = 800, cx = 320, cy = 240）。

u = 800 × 0.38 + 320 = 304 + 320 = 624 （理想なら 640）
v = 800 × 0.285 + 240 = 228 + 240 = 468 （理想なら 480）

右下の縁に写るはずだった点が、横に 16 px、縦に 12 px だけ中心寄りに写りました。 画像の隅で 20 px 近いずれは、マーカーの 1 px を距離に換算していた前のページの感覚からすると巨大です。 歪みを無視した姿勢推定が端で大きく狂う理由がここにあります。

グリッドは正規化座標に等間隔で引いた直線です。 中心付近はほとんど動かず、端ほど大きくずれることを確かめてください。 k2 だけを動かすと、中央部はそのままで四隅だけが動きます。 r⁴ は r が小さいところではほぼ 0 だからです。

放射歪みのほかにもう 1 種類、レンズとセンサが完全には平行に組み立てられていないことによるずれがあり、 これを接線歪みと呼びます（係数は p1, p2）。 放射歪みと接線歪みの両方を含めた、標準の 5 係数の式は次のとおりです。

OpenCV の標準 5 係数モデル
x″ = x′·(1 + k1r² + k2r⁴ + k3r⁶) + 2p1·x′y′ + p2·(r² + 2x′²)
y″ = y′·(1 + k1r² + k2r⁴ + k3r⁶) + p1·(r² + 2y′²) + 2p2·x′y′

前半の括弧が放射歪み、後半の p の項が接線歪みです。 まともに組み立てられたカメラでは p1, p2 は小さく、 まずは k1 が支配的だと覚えておけば十分です。

OpenCV が返す配列 distCoeffs の並び順は (k1, k2, p1, p2, k3) です。 番号順ではなく k3 だけ最後尾に付くので、値を読むときに取り違えないよう注意してください。 なお 5 個というのは既定の設定での話で、オプションで高次のモデルを選ぶと配列は 8 個や 12 個、14 個に伸びます。 このページの範囲では 5 個のモデルだけ分かれば十分です。

歪み補正は、この式の逆向きの計算です。 cv2.undistort は、歪み係数を知っている前提で「歪んだ写真から、理想のピンホールで撮ったような写真」を作り直します。 係数を知るところまでがキャリブレーション、使って戻すのが歪み補正、という分担です。

キャリブレーションが求めるもの

キャリブレーション（カメラ校正）とは、ここまでに登場した数の一式、 すなわち K の中の 4 つ（fx, fy, cx, cy）と歪み係数 5 つを、 手元のカメラ個体について実測する作業です。

fx はレンズの焦点距離と画素サイズから計算できるはずでした。 それでも実測が要るのは、仕様書の値が個体の現実と一致しないからです。 レンズの取り付け位置は 1 台ごとに微妙に違うので主点は中心から数ピクセル単位でずれ、 フォーカスやズームを動かせば fx も変わります。 歪み係数にいたっては、そもそも仕様書に載っていません。

実測の道具は、寸法を正確に知っている平面パターンです。 チェスボードや、ArUco マーカーを碁盤に並べた ChArUco ボードがよく使われます。 パターンを角度や位置を変えて何枚も撮影すると、 「世界座標でここにあると分かっている点が、ピクセル座標でここに写った」という対応が何百組も手に入ります。 キャリブレーションの計算は、その対応すべてを最もよく説明する K と歪み係数 （と、各写真での R, t）を探す最適化です。 構造は前のページの締めで見た solvePnP と同じで、未知数に内部パラメータまで含めた大型版だと言えます。

cv2.calibrateCamera の入出力 
ret, cameraMatrix, distCoeffs, rvecs, tvecs = cv2.calibrateCamera(
    objectPoints,   # パターン上の点の世界座標（寸法から自明）
    imagePoints,    # 検出されたピクセル座標
    imageSize,      # (幅, 高さ)
    None, None)

# cameraMatrix = [[fx,  0, cx],      ← このページの K
#                 [ 0, fy, cy],
#                 [ 0,  0,  1]]
# distCoeffs   = [k1, k2, p1, p2, k3] ← 歪み係数
# rvecs, tvecs = 各写真の R, t（外部パラメータ）
# ret          = 全点の RMS 再投影誤差（px）。0 に近いほど良い

返ってきた cameraMatrix の対角に並ぶ 2 つの数が「比をピクセルに直す拡大率」、 右端の列が「主点の位置」、distCoeffs の 5 つが「レンズの癖」。 このページの計算を手でなぞった今なら、数字の一つひとつが読めるはずです。

ret は、推定したパラメータで 3D 点を投影し直したとき、 実測のピクセル位置と平均でどれだけずれるかを表す値です（RMS は 2 乗平均平方根の意味）。 出来栄えの手軽な指標になりますが、良し悪しの線引きは解像度やコーナー検出の精度、用途によって変わります。 この 1 つの数字だけで合否を決めず、写真ごとの誤差や、パターンが画面の隅まで写っていたかも併せて確認してください。

内部パラメータ K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]

奥行きで割った比を、拡大（fx, fy）と平行移動（cx, cy）でピクセルに写す。カメラを動かしても変わらない。

歪み係数 (k1, k2, p1, p2, k3)

理想のピンホールと実物のレンズの差。正規化座標の上で、中心からの距離に応じて点をずらす。

次のステップ ArUco 検出 → solvePnP

K と歪み係数が手に入れば、マーカー 4 隅のピクセル座標から R, t（マーカーの位置と姿勢）を解ける。キャリブレーションはそのための前準備。

数値はすべてページ内でリアルタイムに計算しています。 座標系は OpenCV の規約（カメラ座標は X 右・Y 下・Z 前方、画像は左上原点）に従い、 例では 640×480 px、fx = fy = 800 px、主点 (320, 240) を標準値としています。 歪みモデルは OpenCV の calib3d モジュールと同じ定義です。
